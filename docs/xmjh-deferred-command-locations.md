## 已删除系统：后续裁剪剧情

### 性格查询

`CHARACTER_MENU` 共 2 处，位于 `storysPY.xml`：

- `孩子_查询性格n`
- `神秘少女查询性格`

两处原参数均为 `神秘少女#1`。性格系统已决定删除，因此这些剧情段应在后续内容清理时删除或改写；运行时不增加空实现。

### 预设人格 / 魂穿人格

`SET_CHARACTER` 共 14 处：

- `storys.xml`：`狄云魂穿剧情`、`独孤求败魂穿剧情1`、`田伯光魂穿剧情`、`郭靖魂穿剧情`、`黄蓉魂穿剧情`

`SET_CHARACTER2` 共 8 处，均位于 `storysPY.xml` 的 `生孩子_性格1` 至 `生孩子_性格8`。例如第一段为：


该人格系统已删除。这些剧情在作者重写或裁剪前仍保留 `unsupported-command` 警告；运行到此处会跳过指令，因此人物生成可能处于半完成状态，不能把它们视作已经迁移完成。

## 隔离原则

- 明确延期或已删除系统的指令仍应被隔离报告标记为 unsupported，不能用空命令伪装成已适配。`unsupported-command` 本身不会剔除剧情段，而是作为运行时可跳过警告；`unsupported-query` 会真正隔离分支段。
- `depends-on-quarantined` 是连锁影响，不等于出现了新的未知指令；应先解决最底层的 unsupported 或 missing target。
- 每次重新转换三份权威 XML 后，应重新生成 `story-isolation.json`，以该报告核对清理结果。
